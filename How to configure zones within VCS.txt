I strongly recommend that you move over the service group to the second system and run the following:
 
sunsrv1: zoneadm -z myzone detach

sunsrv1: hagrp -switch myzone -to sunsrv2
sunsrv2: zonecfg -z myzone create -a /zones/myzone
sunsrv2: zoneadm -z myzone attach
sunsrv2: zoneadm -z myzone boot
sunsrv2: zlogin myzone
 
Make sure all is fine, then init 0.
 
sunsrv2: zoneadm -z myzone detach
 
Move all back to primary and online the service group.  Not doing this process will result in the monitor script not being able to tell state on the second node.  As it will not be in /etc/zones/index.
 
Now comes the fun part.  Creating the specialized start/stop/monitor scripts for the local zone.
 
sunsrv1: hares -link myzone_zone zroot_myzone

sunsrv1: hares -modify myzone_zone Enabled 1
sunsrv1: hares -online myzone_zone -sys sunsrv1 
Adding the IP and NIC connections for the zone.  This is a little bizzar.  The NIC agent is configured in the Global Zone, and the IP is set to the attribute ContainerName.  Once this is done, you do not need to specify the NIC device in the zone.xml file.  It will just appear. They you can update the zones name space.
 
sunsrv1: hares -add myzone_nic NIC myzone
sunsrv1: hares -modify myzone_nic Device hme0
sunsrv1: hares -modify myzone_nic Enabled 1
 
sunsrv1: hares -add myzone_ip IP myzone
sunsrv1: hares -modify myzone_ip Address 10.1.1.5
sunsrv1: hares -modify myzone_ip Network 255.255.255.0
sunsrv1: hares -modify myzone_ip ContainerName myzone
sunsrv1: hares -link myzone_ip myzone_nic
sunsrv1: hares -link myzone_ip myzone_zone
